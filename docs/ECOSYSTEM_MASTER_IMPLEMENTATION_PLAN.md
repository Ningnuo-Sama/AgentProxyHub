# Agent-first 生态统一实施计划书（拍版候选 v1）

> 状态：用户已于本轮拍版，进入候选实施阶段。本文件授权按范围开发、隔离验证和统一集成；不代表任何未验收版本已上线，也不授权外部付费、随机微信发送、删除数据或扩大认证权限。
> 目标：用户完成必要登录/授权后，系统后台自主运行；用户只接收必要告警和最终收口报告。
> 原则：减少用户入口，不减少专业能力；合并重复控制面，不强行合并不同运行时；先候选验证，再正式切换；所有“已实现”必须有代码与真实运行证据。

## 0. 本次拍版范围

本计划综合前面所有已确认方向，包含：

1. AgentProxyHub 作为网络事实源与自动运维控制面；
2. Flow-Tools 短令牌/账号池自愈与媒体任务可靠性；
3. Antigravity 对话网关会话恢复；
4. CloakMulti 登录后自动纳管 Flow；
5. Visual Pro 作为独立 Python 视觉服务；
6. 无限画布保持自主创作，Visual Pro 只做用户主动调用的深度优化；
7. 微信/手机分身作为入口、通知和后续多人交付终端；
8. GLM-4flash 作为运维复杂判断插件；
9. 运维面板精简，创作面板不被削弱；
10. 2FA/CAPTCHA 授权适配边界；
11. 统一任务、事件、能力和收口报告协议。

多人微信创作列入完整范围，但在消息身份与媒体定向发送闭环之前不宣称完成。

## 1. 最终软件地图

| 组件 | 必须独立的原因 | 最终职责 | 不再重复建设 |
|---|---|---|---|
| AgentProxyHub | 网络核心、端口池、mihomo与账号出口身份是独立运行边界 | 节点、端口、绑定、探活、订阅、网络自愈、AutoPilot | 独立Orchestrator、多个代理巡检器 |
| Flow-Tools | Google Labs媒体协议、账号池、点数和异步媒体任务独立 | 生图/视频执行、账号/Token生命周期、任务与产物 | 第二套媒体账号库 |
| Antigravity | 对话协议、OAuth账号与会话粘性独立 | Gemini/LLM对话网关、账号调度、会话恢复 | 外部直接改其私有账号库 |
| CloakMulti | 浏览器/Profile/认证资料和登录交互独立 | Profile、浏览器、登录、2FA/CAPTCHA入口 | 独立代理真理账本 |
| Visual Pro | 视觉理解和媒体生产编排是独立Python服务，但不需要编码Agent常驻 | 画布深度优化、微信/LLM视觉创作、模型/渠道/成本建议 | 新建AI Gateway、桌面App、编码Agent运行依赖 |
| 无限画布 | 用户创作工作流和节点执行边界独立 | 节点、素材、创作方式、模型选择和生成 | 被Visual Pro强制接管 |
| 手机分身 | Android Root、微信客户端和设备通信独立 | 微信入口、通知、后续定向媒体交付 | 独立AlertBridge产品 |
| GLM-4flash | 轻量决策插件，不拥有业务状态 | 运维复杂故障归纳与候选排序 | 独立GUI和凭据库 |

用户日常只需要 Agent、CloakMulti 登录入口、微信/画布创作入口。后端组件不要求用户分别维护。

## 2. 总体运行方式

```text
用户/微信/无限画布
        │
        ▼
Agent或画布节点
        │
        ├─ 运维动作 → AgentProxyHub AutoPilot
        ├─ 对话请求 → Antigravity
        ├─ 视觉深度优化/微信视觉创作 → Visual Pro
        ├─ 媒体生成 → Flow-Tools或其他已验证渠道
        └─ 手机通知/交付 → 手机分身适配器

AgentProxyHub只管理网络事实与运维状态；Visual Pro只管理视觉方案和媒体编排；不互相复制完整业务账本。
```

Codex、Claude Code和CLI是开发/诊断工具，不是Visual Pro运行基座。Visual Pro继续以本地 Python HTTP 服务运行（当前 127.0.0.1:8320），需要补齐任务持久化、上下文组装和受控工具调用，但不新增大型Agent平台。

## 3. 权限和自治原则

### 3.1 默认自动执行

在既有权限和策略范围内，Agent可自行：

- 探活、刷新订阅、重载配置、回退配置；
- 严格同国切换和同国跨provider恢复；同大区但跨国默认升级，不以同洲替代国家策略；跨国不自动作为普通恢复路径。
- 冷却坏账号、迁移新任务、查询未知提交；
- 受支持的凭据续期、Flow资料同步、Antigravity会话解锁；
- 对明确失活且路径/PID核验一致的服务执行有界重启；
- 使用已授权2FA处理本人管理账号的真实认证步骤；
- 生成脱敏状态报告和重要事件通知。

### 3.2 必须升级

以下不静默越过：

- 新增服务授权或OAuth同意；
- CAPTCHA真实接入路径尚未有本地技术契约；
- 主体不一致、跨国/跨大区高风险漂移；
- 凭据泄漏、数据损坏、收件对象无法确认；
- 全部可用资源持续不可用；
- 可能重复扣费或超出预设媒体预算；
- 数据删除、远端发布、权限扩张。

CAPTCHA授权已记录，但实际调用须等待 `D:\GitHub\CAPTCHA` 技术文档，确认目标服务认可/无障碍路径、域名白名单、审计与撤销。2FA只在对应账号真实认证上下文使用。

## 4. 统一协议

### 4.1 能力注册表

Agent不记忆散落端口和私有字段，调用版本化能力：

```text
observe / plan / execute / verify / pause / resume / report
proxy.recover
flow.refresh_account
flow.query_task
flow.sync_profile
antigravity.recover_session
visual.deep_optimize
visual.plan
visual.generate
notify.wechat
```

能力注册表记录执行者、版本、参数Schema、权限、费用级别、超时、回滚方式和真实验证状态。未知能力只能进入候选，不自动调用。

### 4.2 统一任务对象

```text
task_id, owner, source, capability, input_refs,
policy_version, binding_revision, status, attempts,
cost_state, output_refs, delivery_status, error
```

同一任务必须幂等；提交结果未知先查询，发送失败只重发原产物，不重新生成。

### 4.3 统一事件对象

```text
event_id, dedupe_key, severity, component, account/profile,
binding_revision, reason, action_required, created_at, expires_at
```

日志不保存Cookie、Access Token、Refresh Token、订阅链接、完整邮箱或原始请求正文。

## 5. 工作包WP-00：横切安全、能力与持久化底座

WP-00是所有工作包的前置契约，由主会话统一维护，不由单个子项目私自复制。

### 必须统一的事实

- 唯一生产绑定读写入口、真实运行路径和数据根；源码根与 `D:\Program Files\AgentProxyHub` 不能混用；
- 能力注册、任务/事件Schema、策略版本、预算、取消、幂等键、replay防护和审计字段；
- `bindings.json` 的跨进程锁、原子写、revision/CAS、解析失败禁止写空账本；Cloak与Hub消费者必须共享同一锁和生产路径；
- 主会话使用的恢复链不能依赖正在被维护的8045网关或mihomo控制链，必须有独立的本地状态/回退入口；
- 模型输出只允许严格Schema内注册能力，确定性恢复不依赖LLM；GLM失活时回退规则路径；
- 任务提交遵循 `persist-before-send`、客户端幂等键、`submission_state=unknown`、上游task/operation_id和账户/出口租约；unknown只能查询或人工核对，不可直接重生；
- 状态与权限分离：用户手工排除、security quarantine、cooldown、余额可见、业务能力不得混为一个healthy标志。

### WP-00验收门槛

错误Key、过期op、重放、未知能力、非Schema模型输出、损坏账本、CAS冲突、未知提交、未知费用、取消和预算耗尽均须无越权副作用。WP-00未通过，其他工作包只能候选，禁止统一切换生产。

## 6. 工作包A：AgentProxyHub网络托管

### 实施

1. 核验源码、正式副本、PID、端口和账本路径；
2. 明确唯一生产绑定读写入口；
3. `bindings.json`补跨进程锁、原子写、revision和回读；
4. 节点按稳定身份映射，订阅顺序变化不得重排现役端口语义；
5. provider独立刷新，生成差异、校验配置、热重载、真实探活；
6. 失败自动回退，局部provider故障不重建全池；
7. 保留 `21001-21080`、`22001-22045`；
8. 认证/关键任务排空或有界取消后再切换出口；
9. 不用不受约束的AUTO-POOL承载身份敏感账号。

### 验收

- 单节点失效自动恢复；
- provider失效不影响其他provider；
- 坏配置自动回退；
- 并发写账本不覆盖；
- 节点重排不改变既有Profile/账号语义；
- curl `socks5h` 实测出口、国家码和PID路径一致；
- 旧版本可恢复。

## 6. 工作包B：Flow短令牌与账号池自愈

### 6.1 凭据层级

```text
Cloak/Flow Profile
  ├─ Google Cookies /资料
  ├─ Session Token（ST）
  └─ 出口绑定
          ↓
       ST换票
          ↓
       Access Token（AT，短寿命）
          ↓
       点数/项目/生图/视频请求
```

AT必须使用实际过期时间或保守寿命，禁止伪造24小时。`accounts.json`、`browser-profiles.json`、Hub `bindings.json`分属不同事实源，不合并。

### 6.2 自动状态机

```text
healthy → at_expiring → refresh_at → verified → healthy
refresh失败 → existing_ST换票 → verified
ST失败 → 新鲜Profile/Cookies提取 → 受支持重认证 → ST → AT → 点数+最小业务验证
失败 → cooling/quarantined → 备用账号继续 → 必要时微信
```

每步记录脱敏 `account_id/profile_id/binding_revision/proxy/country/attempt/generation/expires_at/reason`。

### 6.3 自动行为

- 周期提前刷新AT；
- 401/403/429/5xx分别分类；
- 单账号连续401只隔离单号；
- 资料正在使用时等待，不强杀；
- ST失败时不能用旧Cookie无限重试；
- 点数REST回退只证明点数观测，不证明生图/视频权限；
- 重启后恢复账号、任务和刷新队列，不把空列表标为健康；
- 修改DPAPI数据前备份，解析失败立即停止，tmp+rename+回读终验。

### 6.4 验收

AT过期换票、ST失败新鲜资料恢复、单号隔离、Flow重启接续、文件损坏保护、点数与真实最小图片任务分别通过。视频使用最低已授权规格验证；未知或外部付费立即暂停，不自动购买。

Flow官方双上游（协议与凭据提取）是异常排查第一事实源；遇到401/403、空帧、协议变化或凭据失效，先检索上游commit/Issue/PR，再移植验证方案。

## 7. 工作包C：Antigravity会话恢复

- 400/401/429/5xx按语义分类；
- 只解除受影响会话粘性，不清空全网关；
- 请求/账号/全局分别有重试预算；
- 坏账号冷却，其他账号继续；
- 只使用管理接口/CLI，不从外部写私有账号库；
- 保持现有出口绑定与`socks5h`约束；
- `/health`与真实最小对话同时验收。

## 8. 工作包D：Cloak登录后自动纳管Flow

```text
Cloak登录完成
→ Profile空闲/资料关闭事件
→ Flow sync-profile兼容路径
→ account/profile/主体/出口校验
→ staged → validated → active
```

实现幂等导入、管理鉴权、主体匹配、服务内加密保存、失败不覆盖旧账号。Antigravity新增OAuth权限仍走其自身授权，不把一次Google登录假定为全服务授权。

## 9. 工作包E：Visual Pro视觉服务

### 9.1 双模式

**画布增强模式**：画布节点保留创作和生成权。Seedance首个试点并列：`优化提示词` 与 `Visual Pro深度优化`。后者读取当前节点直接关联图片/视频/音频、提示词、素材角色、模型、创作方式、参数和相关经验，输出提示词、可选参数补丁、能力/成本诊断。默认不提交生成、不换模型、不覆盖原稿；用户应用后才写回，支持撤销和过期版本保护。

**微信/LLM模式**：Visual Pro维护草稿和订单，负责理解、追问、方案、低成本渠道选择、提交、查询、落盘和交付编排。用户指定模型时严格服从；未指定时优先已验证且满足需求的本地Flow低成本能力。Flow不是用户需要直接管理的第二入口。

### 9.2 运行底座

保持Python常驻HTTP服务；Gemini理解默认走本地反代 `gemini-3.8-flash`。LLM额度字段只在后台预留，默认不外显；不用Codex/Claude Code/CLI作为运行依赖。OpenViking/本地经验只按相关内容检索，首版只记录与检索，不自动改写经验、技能或模型。

图片可直接多模态分析；视频输入方式和全片/抽样覆盖按实际接口核验，不能凭模型名声称已看完整视频。内容哈希+节点版本+模型/经验版本缓存分析，事件触发，不让LLM持续空转。

### 9.3 成本治理

成本判断同时考虑金额/积分、账号配额、风控成本、等待时间和失败重试成本。免费或近免费状态必须依据当前账号资格和回执，不硬编码永久免费；外部付费API默认不自动调用。真实媒体任务仍遵守现有确认与最低额度测试门槛。

## 10. 工作包F：无限画布和面板减法

画布不是运维面板，保留模型、模式、素材、参数和节点自主执行。Visual Pro只做主动增强。

运维面板默认只显示：总体状态、当前任务、待人工事件、暂停/恢复、报告。节点评分、逐端口探活、账号池维护、Key、详细路由进入高级入口或由Agent执行。既有功能不批量删除，先收敛默认入口。

Visual Pro现有 `/panel`降为诊断面板：服务健康、当前任务、最近产物、失败任务和停止任务；不新增桌面App。

## 11. 工作包G：手机分身与多人微信创作（后续）

手机分身保持独立，不接管Hub代理账本。微信通道复用现有本地链路；手机只接收脱敏事件、执行白名单动作和交付媒体。

多人创作采用后台Inbox/Outbox：不同会话并行、同会话有序、手机发送串行但不阻塞LLM/生成。每单绑定会话ID、发件人ID、草稿版本、订单ID、任务ID和产物ID。先验证两个测试会话交叉收发文字/图片，再扩视频和多人；禁止通过“当前窗口/最近联系人/相册第一张”推断收件人。

## 12. 通知、认证与恢复

可替代资源仍可交付时静默；普通续期、换线、冷却、重试成功静默。整体不可用持续阈值、必须本人授权、主体不一致、凭据泄漏、数据损坏、错误收件风险才微信。通知状态区分入队/提交/可验证送达；断线持久化，恢复后只补发仍有意义事件。

## 13. 实施顺序与并行方式

### 当前P0封锁（必须先闭环）

在WP-00、Hub同国/账本一致性、Flow主体/健康分层/未知提交、以及当前网关不自断门禁通过前，任何候选不得正式切换。已发现的高风险旧路径包括：无同国候选时全局最快跨国回退、直接外写Antigravity私有配置、按进程名宽泛强杀、账本解析失败写空对象、Flow点数成功即解除排除、资料邮箱先upsert后主体校验、HTTP刷新不等价于完整自愈、未知提交重新POST。它们必须被删除、隔离或改为fail-closed，并有对应测试证据。

主会话正在使用的8045网关、mihomo和通知链不得由任何子Agent重启或切换；候选进程必须使用独立数据根、资料根、产物根和非生产端口，不能只通过改监听端口宣称隔离。


### 先行并行

- A：AgentProxyHub网络事实源和自愈；
- B：Flow短令牌、账号池和媒体任务恢复；
- C：Antigravity会话恢复；
- D：Cloak→Flow登录纳管；
- E：Visual Pro服务契约可并行开发，但不绕过Flow/Hub实际事实。

### 集成阶段

- F：Seedance深度优化、画布并列入口和运维面板收敛；
- G：微信可靠通知、手机多人创作与定向交付。

本节编号与第5—11节工作包保持一致；Cloak与Flow不合并职责，E的Visual Pro契约先于F接入。

主会话是集成负责人。各工作包独立候选目录/文件Owner；不抢生产端口、不改正式数据、不各自上线。最终按完整集成版本重新构建、验收和切换。
