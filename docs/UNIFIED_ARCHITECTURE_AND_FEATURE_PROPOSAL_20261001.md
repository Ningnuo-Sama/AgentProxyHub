## 二、模块一：手机分身 · 智能双轨与降级容灾体系 (未落地设计)

### 2.1 已经实测证伪并彻底废弃的方案
* **废弃「串行两级接力（GLM 前台接待规划 ➔ 传递简报给 Gemini 生成）」**：
  * **实测缺陷**：串行双模型导致端到端耗时累计至 10~16 秒；Gemini 3.8 Flash Tiered 具备数百至上千 Token 的原生隐式深度推演能力，GLM 吐出的粗粒度 JSON 简报不仅无法提供增益，反而稀释了上下文，属于严重负收益。

### 2.2 核心待落地架构：单兵主战 + 应急冷备与摇人机制
1. **第一优先级（Level 1·常态 100% 运转）：`Gemini-3.8-flash-tiered` 单兵全权接管**
   * **运行参数**：直连本地 `http://127.0.0.1:8045/v1`，必须赋予 `max_tokens >= 1800`（吸收 Tiered 推理 Token 预算）。
   * **职责**：
     * 高情商去 AI 味日常拟真社交（妻子查岗、日常闲聊）；
     * 涉及借钱、线下约见签合同等敏感行为，具备铁血审查与输出 `[NEED_MANUAL_TAKEOVER]` 挂起人工接管的能力；
     * Root 底层指令（私有缓存提取、`dumpsys battery` 硬件温控、小红书 Hook 逆向）。
2. **第二优先级（Level 2·低优先级冷备）：`GLM-4-flash` 应急接管**
   * **触发条件**：
     * Gemini 本地网关 8045 超时（默认硬阈值设为 4.0 秒）；
     * 代理链路断开或网关返回 5xx / 429 报错。
   * **执行约束（防翻车核心准则）**：
     * GLM 在实测中表现出“擅自答应线下签约”、“公文道歉体”等下位模型特征。
     * **强制约束**：进入 GLM 应急兜底时，其系统 Prompt 必须被严格改写为「应急拖延稳住模式」——仅允许使用真人合理借口（如“刚在路上看手机卡了，稍后看”、“手头有急事，晚点回电脑前核对”）稳住对方，**绝对严禁擅自做决定、承诺排程或答应合同**。
3. **“去摇人”通知闭环（待工程化实现）**：
   * 一旦降级到 GLM 顶上，系统必须立刻触发双向告警：
     * 控制台高亮标红：`[WARN] Gemini 链路故障，GLM 已应急代发稳住对方，请检查网络！`
     * 手机端推送：通过 Root 手机发送本地通知栏提示或 SMS/微信告警通知主人。
4. **短回复极速分支（待评估）**：
   * 针对 5 字以内极短确认（如“取快递”、“收到”），是否开放走 `gemini-3.8-flash-low`（低思考档，首字 1.4 秒）或 GLM 直连（首字 0.89 秒）快车道。

## 三、模块二：AgentProxyHub · Credentials Vault 凭据金库 (全新未落地架构)

### 3.1 核心战略拍板：放弃独立 AgentKeyHub，全面大一统并入 AgentProxyHub
* **理由**：发起 AI 调用必须同时具备“钥匙（API Key / Base URL）”与“道路（Proxy 出口端口）”。将两者拆分将导致多项目重复配置、多面板割裂。

### 3.2 待落地的核心凭据模块：`core/vault_manager.py`
1. **本地硬件级加密存储**：
   * 拒绝明文 `.env` 散落及误推 Git 风险；
   * 在 Windows 平台基于 **DPAPI（`CryptProtectData`）** 或本地唯一机器 GUID 生成密钥；
   * 密文持久化至 `D:\GitHub\AgentProxyHub\data\vault.enc`。
2. **凭据双轨分类与物理隔离模型**：
   * **轨 A：模型与业务消费级 Key（允许分发与代理）**：
     * 包括：Google Gemini、智谱 GLM、Kie-AI、TTAPI、SiliconFlow、OpenAI 等；
     * 属性：Provider、Base URL、Key（脱敏）、绑定的 Proxy 出口端口（如 21012）、超时阈值、备注。
   * **轨 B：系统级与云存储高危凭据（沙盒锁死，绝不外发）**：
     * 包括：火山引擎 TOS AK/SK、阿里云 OSS AK/SK、GitHub Token、AWS 密钥；
     * 物理约束：此类密钥**绝对不允许**作为 HTTP Authorization Header 经由任何网络端口对外转发，**仅限在本地内存中执行 HMAC-SHA256 SigV4 预签名运算**。
3. **驻场工程师（Agent）凭据接管网**：
   * **铁律 1（不刺探）**：严禁中枢主动递归遍历用户全盘扫描抓取敏感配置文件；
   * **铁律 2（人工投喂智能分流）**：用户在对话中随手粘贴一段混乱的文本或代码片段，工程师通过正则与意图解析器自动提纯：
     * 识别出模型 Key ➔ 自动测速并归入【模型通信池】；
     * 识别出云厂商 AK/SK ➔ 自动归入【存储签名沙盒】，并向用户明确报告隔离状态。

## 四、模块三：智能路由分流与防偷 Key 盲中转机制 (未落地设计)

### 4.1 智能分流与防绕路矩阵（核心路由算法）
系统必须具备以下明确的分流规则，严防“给本地反代套代理”的致命低级错误：

| 目标类型 | 典型端点 | 网络策略 | 为什么必须这样设计？ |
| :--- | :--- | :--- | :--- |
| **本地私有反代** | `127.0.0.1:8045`<br>`127.0.0.1:8001`<br>`127.0.0.1:8320` | **强制 `NO_PROXY`**<br>(0ms 物理回环) | 进程就在本机。若套代理，流量会飞去海外代理再试图连本地 127.0.0.1，必死无疑或产生数百毫秒死锁。 |
| **国内高速通道** | `open.bigmodel.cn`<br>`api.ttapi.org` | **国内直连 (Direct)**<br>(20~40ms / 490ms) | 实测证实智谱国内 API 挂海外家宽代理延迟飙升 300%~500%。国内接口坚决不走梯子。 |
| **双节点中转站** | 国内加速节点 + 海外备用节点 (如某些聚合中转) | **国内直连优先 + 静默海外重试** | 平时 100% 走国内节点（免代理、低延迟）；遇国内 5xx 故障，网关层静默换线海外代理重试，下游业务零报错。 |
| **海外原厂受限 API**| Google 官方原厂<br>OpenAI 官方原厂 | **绑定 AgentProxyHub 专属出口**<br>(Socks5 `210xx` / HTTP `310xx`) | 必须由 AgentProxyHub 实施分国别 IP 隔离与粘性保持，防止账号被 Google/OpenAI 风控封禁。 |

### 4.2 避免第三方中转站“偷 Key”的硬核机制
1. **本地虚拟 Token 代发（假 Key 模式）**：
   * 业务项目（手机分身等）统一打给本地中枢，携带虚拟 Token `hub-local-token`；
   * 中枢在本地内存中将 Header 置换为真实 Key 后直接发给官方，真实 Key 绝不流出本机。
2. **盲代理（HTTPS CONNECT 隧道）**：
   * 对外部代理节点只建立纯 TCP 隧道，TLS 握手在本地与官方服务器完成，中间代理节点只能看到加密密文，无法解析出 HTTP Authorization 头。

### 4.3 极简可视化本地 Web 弹窗 (Dashboard)
* **形态**：在托盘或命令中拉起一个轻量本地 Web 服务（监听高位安全端口，如 `127.0.0.1:32000/keys`）。
* **功能**：
  * 卡片/表格化展示各渠道：名称、协议、Base URL、Key（脱敏打码+一键复制）、绑定代理出口、实时探活延迟、自定义备注；
  * 支持前端在线编辑 Key 和备注，点击保存即时触发本地加密持久化，热更新全局生效；
  * 提供一键全渠道连通性巡检测试按钮。

## 五、模块四：多模态生图/视频与垫图图床基础设施 (未落地标准)

### 5.1 Midjourney 渠道与网络策略标准化
* **确认事实**：Midjourney 生图走 **TTAPI（`api.ttapi.org` / `api.ttapi.io`）**，与 Kie 平台完全无关。
* **网络策略**：
  * TTAPI 国内直连通畅（`api.ttapi.org` 延迟仅 494ms），**严禁挂海外代理**；
  * **防 403 规避**：TTAPI 网关位于 Cloudflare 盾后，请求头必须固定携带标准浏览器 User-Agent（如 `Mozilla/5.0 ...`），否则会被拦截。

### 5.2 垫图图床机制（火山引擎 TOS 标准化集成）
* **必须有桶的根因**：
  * Midjourney 垫图语法强制要求在 Prompt 前缀带上公网可访问的图片 URL（`https://.../ref.png prompt --ar 9:16`）；
  * TTAPI 官方不提供文件上传接口（`/upload` 报 404）；
  * 免费第三方图床存在超时导致 TTAPI 任务被判失败的痛点。
* **待落地工程契约**：
  * 在 AgentProxyHub 凭据库中统一标准化配置火山引擎 TOS（AK、SK、Bucket、Endpoint `tos-cn-beijing.volces.com`）；
  * 封装统一的本地上传与签名工具（`upload_and_sign`），基于本地 HMAC-SHA256 生成 7 天有效的预签名公网直链；
  * 下游项目（手机分身、Ariadne、画布）只需调用一行代码即可完成本地图片上桶并换回 URL，彻底解决垫图与视频首尾帧问题。
