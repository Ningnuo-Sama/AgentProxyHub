# AgentProxyHub 全网互联流动图复核标注

复核对象：`agentproxyhub-panoramic-flow.html`

## 总结

这张图的**架构方向基本正确**：上游凭据 → 出口池 → 探测/置信度 → MCP → 模型/媒体网关 → 画布/浏览器/手机 → 鲸管家/Hermes，主干关系成立。

但图把“代码存在 / 端口健康 / 候选测试通过”大量标成了“已实现”，这与正式验收矩阵不一致。建议把节点状态从二元的“已实现/未实现”改成四态：

- **已验证**：真实业务闭环已跑通；
- **候选/部分验证**：代码和局部测试通过，但生产闭环未完成；
- **只读可用**：能展示或探测，执行链路未开放；
- **未实现/阻塞**：尚不能承诺。

## 必须在图上标红的节点

### 1. AgentProxyHub 正式运行副本

图中 CORE ENGINE、MCP、端口池等节点的方向正确，但源码与 `D:\Program Files\AgentProxyHub` 的正式运行副本一致性需要单独标注“待最终核对”。健康端口不能证明运行副本就是当前源码。

### 2. Antigravity Tools (8045)

当前 `/health` 为 200，但以下内容尚未形成完整验收证据：

- 真实最小对话；
- handler 接入的安全恢复；
- 故障注入与恢复回退。

建议状态：**候选/部分验证**，不要标“全系统模型源·已实现”。

### 3. Flow-Tools (8001)

当前健康，但 reliability contract 尚未完整接入生产：

- 任务事实库；
- operation_id 查询；
- 重启恢复；
- 跨进程锁/CAS；
- 幂等与防重复计费；
- 真实端到端 Release 验收。

建议状态：**候选/部分验证**。图中“免费出图”可以保留，但必须补“可靠性未封闭”。

### 4. Visual Pro (8320)

服务入口存在并有局部测试，但真实 Gemini 多模态 payload、媒体 hash、route/upstream/model 证据尚未完成。

建议状态：**候选/部分验证**，不能把“摆拍/场景接口”直接标为全量已上线。

### 5. Daedalus Canvas (3000) / Canvas Agent (17371)

画布和 MCP 桥的概念关系正确，但尚缺：

- 真实宿主 buildHash；
- 素材 URI 和 64 位 hash；
- 运行时节点资源验收；
- 重启后的真实资源恢复。

建议状态：**候选/部分验证**。

### 6. CloakMulti (7800)

浏览器、端口绑定和 `bindings.json` 共写关系画得正确，但 binding revision/CAS 生产证据和重复同步实跑未完成。

建议状态：**候选/部分验证**。

### 7. 手机真机 / CreationBridge / Hermes 微信链路

图中“端到端生图”“原图回发”“iLink 直推”描述了目标链路，但正式验收仍缺：

- 稳定 sender；
- 稳定 recipient/conversation；
- delivery ACK；
- 断线重启后的补发；
- 已接受但无 ACK 时的防重复发送。

建议将 MOBILE HARDWARE、CREATION BRIDGE、HERMES BOT、SAFETY KILL SWITCH 分别标为：**局部已实现，生产闭环阻塞**。

### 8. 自治中枢

图中把自治工具标为已实现，但当前运行快照返回：`autonomy_state_missing`，自治状态为 `unknown`，不能在图上表示自治服务已经稳定运行。

建议标注：**工具存在，自治运行态未确认**。

## 图中应补充的遗漏模块

### A. 模型路由与降级链

应补一条独立链路：

```text
Gemini 日常 → GLM 兜底 → AICost GPT-6.1-SOL 最高事态
```

同时标明：当前模型策略工具是只读策略，不等于已完成自动切换演练。

### B. 用量、成本和审计

应加入：

- `usage_log`；
- 请求 ID；
- provider/model；
- token 和估算成本；
- 渠道健康记录；
- 清理审计日志；
- 错杀反馈白名单。

这些是 Agent 上线后的可追溯基础设施，不能只画业务流而省略。

### C. 版本/运行副本/回滚层

应加入三层边界：

```text
源码仓库 D:\GitHub
运行副本 D:\Program Files
运行数据 D:\ProgramData
```

并画出：版本核对、候选验证、切换、回滚、数据恢复。当前图只画了能力流，没有画发布安全流。

### D. MCP 客户端重启门禁

应标注：修改 `mcp/server.py` 后，Claude Desktop、Cursor、DSH 等 MCP 宿主必须重启，工具表才会刷新。否则源码新增工具不一定会在前端出现。

### E. 本地回环与代理边界

应明确标出：

- `8045 / 8001 / 8320 / 8766 / 18790` 为本地回环；
- 本地反代不应再次走海外代理；
- `NO_PROXY` 是安全边界；
- `39999` 手机总线与电脑本地服务不是同一条网络语义。

### F. 凭据金库读取者

DPAPI 金库本身画对了，但应补充“谁可以读”：

- AgentProxyHub 本地服务；
- 鲸管家启动链路；
- Gemini 配置解析器；
- 通知令牌解析器。

并标注：只输出给本地子进程的最小必要值，不回显到日志、MCP 返回或前端。

### G. 未纳管渠道

图上应增加灰色节点：

- CLIProxyAPI：当前未运行，按当前决策暂缓纳管；
- root/个人微信：不属于当前 Hermes/iLink 正式边界；
- TOS 图床中继：当前未实现。
