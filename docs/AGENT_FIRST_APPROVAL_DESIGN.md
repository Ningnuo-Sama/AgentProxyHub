## 统一拍版包 v2

### 1. 最终目标与实施边界

用户只需登录账号、表达创作意图、完成确实不可委托的必要授权；正常网络维护、账号纳管、任务恢复和运行判断由后台完成。运维入口收敛，创作界面自由度保留。开发由当前主会话统筹，内部并行，真实验收后统一交付收口报告。

本提案包括前面讨论的全部未完成工作：Hub网络托管、Antigravity恢复、Cloak→Flow纳管、Flow任务恢复、Visual Pro增强与低成本调度、Seedance深度优化、面板减法、微信联动及认证适配。多人微信创作作为后续工作包，不因后置而丢失。

### 3. Visual Pro双模式（不可混淆）

**画布增强模式**：节点直接生成路径保留。Visual Pro仅由用户主动点「深度优化」触发，分析当前节点及直接关联素材，返回提示词和可选参数补丁。默认不改变模型、渠道、素材和创作模式，不提交媒体任务；应用后才写回，支持撤销。分析期间节点改变则旧结果标记过期，不能覆盖新稿。服务离线时原节点与原优化按钮正常工作。

**微信/LLM创作模式**：Visual Pro维护独立会话草稿，理解→必要追问→方案→在预算与授权内提交→查询→保存→交付。用户未指定模型时选择满足需求的低成本渠道；指定模型时严格保留，不静默替换。微信发送由手机适配器执行，不并入Visual Pro核心。

成本排序仅在实际能力满足后进行，不硬编码「Flow永久免费」「所有Flow模型已支持」。核验账号资格、额度和任务回执，未知价格不记成0。外部商业API默认禁止自动调用，既有渠道适配保留但没有自动付费降级权限。

### 4. Visual Pro运行底座与模型

保持现有Python常驻HTTP服务，扩展上下文组装、素材分析、模型适配、任务持久化、工具校验和生命周期接口。当前代码使用ThreadingHTTPServer监听8320；不假定已有完整自治循环、任务恢复或开机守护。

深度理解默认连接现有本地反代gemini-3.8-flash；核验实际endpoint、鉴权、模型ID、图片/视频/音频能力。代理是本地入口，不声称Gemini离线本机推理。LLM额度字段仅后台预留、默认不外显；不可用时返回可恢复状态，不自动转外部付费模型。

短任务事件触发；长任务等待由服务和队列承担，不让模型持续轮询。素材哈希+节点版本+模型/经验版本共同决定缓存；相同分析复用，取消与超时有界。图片可以直接多模态分析，视频按已验证接口直接输入或使用可追溯抽样；抽样结论标记覆盖范围，不假装看过全片。

优先复用现有启动托管能力，允许按需唤醒并确保长任务期间持续运行。不指定新端口，不在未核实前新增服务/定时任务。工程Agent用于建设和诊断，不是日常生产运行依赖。

### 8. 真实案例验收：Flow短令牌失效如何自动处理

这个案例用于检验计划书是否达到可实施颗粒度。历史问题不是简单的“Token过期”：Flow链路同时存在短寿命 Access Token（AT）、较长寿命/可轮换 Session Token（ST）、Google Cookies、账号绑定出口、项目ID和点数读取。过去曾出现把AT寿命伪造为24小时，导致自动续期失效、上游401、号池退化到单账号；也出现过只改 `accounts.json`、遗漏 `browser-profiles.json`，以及DPAPI文件解析失败后继续写入造成空文件的事故。

#### 8.1 正确的数据关系

```text
Cloak/Flow资料 Profile
  ├─ Google Cookies（刷新源，不能当永不过期凭据）
  ├─ ST（会话凭据，可轮换）
  └─ 出口绑定/指纹资料
          ↓ 受支持的 refresh_session
       AT（短寿命业务令牌）
          ↓
     生图/视频/点数/项目请求
```

- AT必须记录服务实际返回的过期时间或明确的短寿命保守值，不能伪造24小时；刷新提前量按实测寿命配置，不能等到请求连续401才处理。
- ST的轮换结果、Set-Cookie和Cookie资料必须按实际协议分类保存；不能因为一次刷新成功就删除旧的可回退信息。
- `accounts.json`、`browser-profiles.json`、Hub `bindings.json`分别由所属项目维护，不合并成一个“凭据文件”；修改前备份，失败即停止，原子写入后回读。
- Flow账号、Cloak Profile、代理端口、实测出口IP和国家码必须形成可核对的绑定快照；同国轮换可按策略重锁，跨国立即隔离并升级。

#### 8.2 自动恢复状态机

```text
healthy
  → at_expiring
  → refresh_at
  → verified
  → healthy

refresh_at失败
  → refresh_st_from_existing_session
  → verified
  → healthy

ST失败但存在Cloak/Flow资料
  → extract_fresh_cookies_or_profile_session
  → supported_reauth
  → refresh_st
  → refresh_at
  → verify_credits_and_minimal_business_capability
  → healthy

无新鲜资料/需要真实登录/主体或区域不一致
  → cooling/quarantined
  → 微信ACTION_REQUIRED
```

具体顺序必须是：

1. 在当前绑定出口上刷新AT；
2. AT失败时，用现有ST尝试换票；兼容 `accessToken` 与 `access_token` 字段；
3. ST失败时，先从已登记且不在使用中的Cloak/Flow资料提取新鲜会话/Cookies，不凭过期磁盘Cookie无限重试；
4. 资料刷新成功后重新换ST、AT，并刷新点数；
5. 仍失败才冷却账号，转移新任务到其他已授权账号；
6. 只有需要用户重新登录、CAPTCHA/2FA、主体不一致、跨区或所有账号不可用时才微信通知。

每一步都必须有 `account_id、profile_id、binding_revision、proxy、country_code、attempt_id、credential_generation、expires_at、reason`，但日志只保存脱敏标识和哈希，不打印令牌原文。

#### 8.3 不能做的“伪恢复”

- 不把AT的名义寿命改成24小时；
- 不把401简单重试成无限换号；
- 不只改Flow `accounts.json`而不核对资料档案和Hub绑定；
- 不使用裸curl结果推断Google会话一定有效；浏览器指纹、出口和Set-Cookie行为可能影响结果；
- 不用陈旧Cookie反复执行无头OAuth；连续两次同类失败即改变路径并隔离；
- 不把点数读取成功当作生图权限一定成功，点数与业务能力分别验收；
- 不因短令牌死亡重建整个账号池，先隔离单账号和受影响任务。

#### 8.4 计划中的自动守护

Flow侧需要提供或核验以下能力，不能只依赖GUI按钮：

- 启动/周期扫描：提前刷新即将到期AT；
- 单账号 `refresh`、全量刷新、热加载和健康回读；
- ST失败后的资料重提取/受支持重登入口；
- 401/403/429分类、冷却和恢复预算；
- 点数REST失败时的已验证前端回退仅作为点数观测，不把它伪装成业务认证恢复；
- 生成前出口、国家码、账号记录三方核对；
- 重启后接续刷新任务，不能把所有账号标成健康或空列表。

#### 8.5 这个案例的验收证据

计划只有在以下证据齐全时才可称为“Flow凭据自愈完成”：

1. 人工构造/隔离一个AT过期账号，自动换票成功；
2. 模拟ST换票失败，使用新鲜资料恢复，且不复制令牌到仓库或日志；
3. 让一个账号连续401，确认只隔离该账号，其他账号仍可完成最小业务；
4. 重启Flow后账号、任务和绑定仍能正确回读；
5. 故意让 `accounts.json` 或 `browser-profiles.json` 备份/解析失败，确认不覆盖原文件；
6. 改变订阅节点顺序，确认Hub端口和账号/Profile语义不漂移；
7. 用最小、已授权的图片任务验证“点数可见 ≠ 业务成功”这一差异；
8. 复核微信只在需要人工时通知，普通续期、冷却和恢复不通知。

现有Flow-Tools维护资料已经记录了部分实现（`SilentKeeper`、`refresh_account`、`/api/manage/reload`、`/api/manage/pin-exit`、前端点数回退、DPAPI与原子写入约束），但这些是项目当前记录的代码/候选证据，不自动等于当前正式进程全部加载；实施时仍需按运行PID、二进制路径、健康接口和真实最小任务重新核验。

既有权限内日常恢复不逐次确认；规则先处理可判定故障，模型仅补复杂决策。管理操作复用所属服务接口，鉴权、幂等、权限和脱敏必备。保留21001–21080与22001–22045；绑定文件不放凭据，不把Flow/Antigravity账号库合并。

用户已授权本人管理账号的2FA真实认证辅助。CAPTCHA独立适配，等待本地技术文档核验服务认可/无障碍路径；不并入Hub网络内核。不能用于规避封禁、访问控制或地域限制。

有替代资源仍能交付时不微信通知；必要本人授权、整体持续不可交付、凭据泄漏或数据损坏时通知。动作预算耗尽先隔离相关对象，只有实际影响需要用户时升级。首次重要告警与结案各一次，不把普通技术日志发微信。

### 9. 面板减法边界

运维面板默认保留状态、任务/报告、必要授权、待人工事件和暂停/恢复；高级维护折叠，不批量删上游能力。Visual Pro现有/panel降级诊断，不新增桌面App。

无限画布是创作工具，不受运维减法削弱：模型/模式/参考素材和生成选择保留。深度优化只是并列入口，不隐藏或取代已有技能。所有按钮有可访问文本、键盘支持、取消与明确状态。

### 10. 实施授权包（下轮统一确认）

推荐一次拍版设计与下列明确授权范围，避免执行期间逐文件请示：

4. 用现有反代作最小LLM验收，媒体测试优先本地Flow已有可用额度，建议单号两张图片；视频待能力确认后用最低允许时长/规格验证，严格不调用外部付费商业API。Flow若会产生额外购买或未知实付费用则暂停该项测试。
5. 微信实测必须有明确测试收件对象：若无法从既有授权找到，不随机选择联系人，唯一必要补充是指定对象。
6. 不删除旧项目/备份，不回写长期知识，不训练模型，不扩大账号/认证权限。

### 11. 交付收口与证据等级

每个工作包区分：设计、代码完成、候选通过、真实验收、正式运行。静态测试不等于真机、构建不等于上线、健康端口不等于业务成功。自行验收覆盖并发、恢复、成本、产物和UI；付费或个人消息未获授权不伪造通过。

全工程结束交付一份收口报告与证据索引；运行中仅必要重要微信通知。报告列真实运行路径/版本、功能矩阵、测试结果、暂停/回退、已完成和待完成事项。过程保留必要的简短进展，不要求用户承担项目协调。

## 早期设计补充（冲突处以v2为准）
> 决策优先级：拍版后本稿取代前期整合文档中相冲突的串行、逐次审批、默认观察期和新增管理平台建议；旧文档作为事实取证保留。
> 范围：AgentProxyHub、Antigravity-Manager、CloakMulti、Flow-Tools、GLM-4flash；手机分身先仅复用已有微信通知。多人创作后置。

## 1. 产品承诺

用户负责初次登录和不可委托的新增服务授权；运行时Agent负责状态判断、网络维护、账号纳管、故障恢复和解释结果。用户不参与节点挑选、改配置、重启网关、搬资料、清理坏会话或日常审批。

默认静默运行、不自动打开面板。完成实施后交付一次收口报告；运行中仅必要人工动作或重大损失风险发微信。能由备用资源完成任务的局部失败不通知。

“自由判断”是可选择并组合既有能力，不是任意shell权限、任意数据库写入或无预算重试。授权由策略确定，计划由Agent生成，结果由执行器真实回读。

## 2. 唯一自动化入口

在AgentProxyHub内扩展轻量AutoPilot，不创建新产品、新大型编排框架或新账号库。

- Hub拥有网络身份、端口映射、绑定与出口切换执行权。
- Cloak拥有Profile和浏览器登录流程。
- Flow拥有媒体账号和任务状态。
- Antigravity拥有OAuth账号、会话和LLM调度。
- GLM锁定glm-4-flash，负责结构化故障归纳和复杂候选判断；确定性规则负责常见恢复。不能因GLM不可用停止普通网络恢复。
- 微信发送器复用现有接口，独立于被监控的LLM网关；不重建手机端。

AutoPilot保存事件、执行计划、检查点、策略版本和回执，不复制各项目账号秘密。网络与账号的详细状态仍归所属服务所有。

## 3. 双层自治

### 快路径：确定性自动恢复

真实探活、同国候选切换、provider订阅刷新、配置回退、账号冷却、受支持凭据续期、任务重查、缓存重载由规则直接执行。不要每次HTTP错误都调用模型。

### 判断路径：Agent选择动作

对复杂/未知故障，Agent获取脱敏现场，生成有限动作计划：诊断→执行→回读→必要时补偿。动作只能引用注册能力，输出严格结构校验。允许跨步骤自主推进，不逐次请求用户确认。

运行Agent不能自行修改自身安全策略、扩大付费预算、下载并执行未知程序或热部署未经验证源码。未知故障可自动收集证据形成修复工单，开发Agent在候选中修复和验证。

### 允许自动做

- 已有权限内同国换节点和跨provider同国切换；
- 在账号配置的合法服务区域内进行恢复；
- 自动隔离坏号并使用其他可用账号完成任务；
- 通过所属服务管理接口续期、导入、重载和恢复；
- 对明确失活进程执行有界、精确PID/路径验证后的重启；
- 调用已授权2FA验证器处理本人管理账号的真实挑战。

### 无法用风险接受替代的边界

不绕过服务访问控制、账号禁用和地域限制，不因普通401/403触发认证破解。CAPTCHA记录用户授权，技术文档到位后核验服务认可/官方无障碍路径，独立适配，不并入Hub网络核心。数据删除、远端发布、新费用及权限扩张没有预授权时不得自行执行。

## 4. Agent接口先于面板

复用已有HTTP/MCP/CLI，补齐薄适配。以下是待实现的能力名称，不代表已有端点：

- observe：获得运行版本、账号能力、网络身份、任务及错误快照；
- plan：依据目标与策略选择处置方案；
- execute：携带op_id、策略版本、绑定revision和有效期执行；
- verify：返回真实结果、状态和证据引用；
- pause/resume：停止新任务或恢复指定对象；
- report：返回脱敏总结和未完成项。

API/MCP与GUI共享业务实现；禁止另写一套面板专属恢复逻辑。管理面认证、权限、幂等、防重放、日志脱敏不能因只监听loopback而省略。

## 5. 面板减法：隐藏操作复杂度，保留接管入口

| 项目 | 默认可见 | 转到Agent/API或高级入口 |
|---|---|---|
| AgentProxyHub | 总体状态、待人工事件、暂停/恢复、报告 | 节点打分、筛选、逐端口探活、订阅、手工绑定、批量导出、置信度详情 |
| CloakMulti | 选择/新建Profile、打开登录、登录/纳管状态 | 代理选择、指纹参数、迁移脚本、凭据同步和维护操作 |
| Flow-Tools | 服务状态、任务/产物、必要登录入口 | 代理池、保活参数、号池维护、模型路由和运维设置 |
| Antigravity | 服务状态、必要OAuth授权、待处理事件 | 手工账号轮换、代理选择、缓存恢复、详细调度设置 |
| GLM-4flash | 不新增GUI | 决策接口与审计记录 |

第一版只改变默认呈现，不批量删除既有功能、历史代码或上游页面。高级入口保留但不常驻主导航；新增控制必须支持键盘与明确文本标签。上游Tauri应用保留现有产品结构，采用本地托管模式/默认入口收敛，避免大面积改上游。

建议仅保留一处统一运行状态入口（现有Hub托盘/状态页），不新增第六个仪表盘。不在每个软件复制统一看板。用户需要诊断时向Agent提问即可。

## 6. 第一批实施：三线并行、单点集成

### A：Hub网络托管

1. 核验源码与当前运行副本，冻结已有未提交改动归属；
2. 定唯一账本路径，原格式兼容，补跨进程锁、原子更新及revision；
3. 节点按稳定标识映射到端口，新增/删除订阅节点不重排现役端口；
4. provider独立刷新，差异校验、mihomo配置校验、热重载、真实探活、回退；
5. 绑定出口引入按账号约束的显式选择，不套用全池url-test；
6. 出口故障先排空在途任务，再切换；认证和关键任务期间保持出口一致。

保留21001–21080与22001–22045。固定端口不等于固定IP，每次底层切换仍记录身份revision并同步消费者。

### B：Antigravity恢复

1. 核实当前错误路径，不依旧交接假定缺陷仍存在；
2. 按语义处理400、401、429、5xx；
3. 仅解除受影响会话，不清空整个网关；
4. 请求级重试预算和账号冷却；
5. 管理适配器实现账号状态/绑定/重载，不外部写私有库。

### C：Cloak→Flow自动纳管与任务恢复

1. 登录完成/资料关闭事件，独立account_id/profile_id映射，不凭昵称识别；
2. 复用sync-profile兼容路径，浏览器忙时等待，不强杀；
3. 服务自有热导入契约：鉴权、幂等、主体检查、加密存储和分阶段激活；
4. 背景同步不要求手动Token；Antigravity额外OAuth权限使用其现有授权流程；
5. 任务提交未知先查状态，保存产物后交付，重发不重新生成；
6. 任务重启接续、取消语义、资源并发限制。

### 主会话：集成负责人

确定接口与文件Owner；子Agent在独立候选/worktree修改，不抢生产端口，不访问生产写数据。汇总后每个项目按完整集成提交重新构建，统一部署、验收、回退记录。执行Agent不独立上线。

面板减法在上述业务能力稳定后做，不为先美化面板阻塞后台交付。GLM与微信适配同期接入，不能成为A/B/C的前置堵点。

## 7. 少打扰的通知策略

以业务影响而非错误次数判定通知：

- 可替代账号/节点仍能完成任务：本地记账，静默；
- 普通故障自动恢复：静默，计入报告；
- 全部目标业务不可用持续5分钟且恢复方案已失败：微信通知；
- 凭据泄漏、数据损坏或错误收件风险：立即停止相关动作并通知；
- 必须本人完成的授权、验证或额度决定：发送一条明确动作请求；
- 已通知事件恢复：一次结案，不刷屏。

发送状态区分入队、客户端提交和可验证送达；没有回执不得宣称用户收到。USB/微信失活时持久化队列，恢复后仅补发仍有意义的重要事件。

用户可随时暂停全部托管。微信命令绑定发送者、对象、有效期和幂等键；不开放任意脚本执行。

## 8. 自行验收与发布门槛

### 自动化测试

- 账本并发抢占、超时、崩溃中断与原子恢复；
- 订阅节点顺序变化、provider离线、重载失败与配置回退；
- 单节点失败、身份改变、在途请求与换线互斥；
- 普通400不重复、坏号不粘死、其他会话不受影响；
- 重复导入、主体不一致、凭据失效；
- 任务未知提交、重启接续、交付失败不重复扣点；
- 错管理Key、权限不足、敏感数据不出日志；
- 微信去重、断线补发、普通事件零消息；
- 精简UI核心登录、暂停、接管和可访问性。

### 真实验证

/health与运行PID/二进制相符；使用明确授权的测试对象验证最小LLM请求、最小图片任务，视频在所需能力与额度确认后进行。微信真实发送仅使用已授权测试接收者。未取得必要测试授权的项目标为待验，不伪称已验收。

首次发布不强制固定24–72小时等待；候选闭环通过后按授权切换，后台持续观察。发布必须保留上一已验证二进制和数据备份；按新→旧→新验证回退，代码回退不覆盖后来新增账号与绑定。

## 9. 收口报告

交付一份报告而不是让用户审核每个技术步骤：

1. 哪些目标已上线、哪些只是候选/待验；
2. 当前进程、版本、启动入口、数据路径；
3. 测试用例与真实链路结果；
4. 普通故障是否零人工干预、重要告警是否可用；
5. 面板减少了哪些默认入口，Agent具备哪些操作；
6. 当前限制、回退方式及必须用户处理的唯一事项。
