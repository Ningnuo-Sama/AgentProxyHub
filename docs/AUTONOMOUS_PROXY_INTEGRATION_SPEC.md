## 一、 项目终极定位与用户体验目标

### 1. 一句话定位
以 **AgentProxyHub** 为底层网络出口调度中枢，横向打通 **CloakMulti**（账号环境与录入）、**Flow-Tools**（Google Labs 生图/生视频）、**Antigravity Tools**（Gemini/Claude 大模型反代），并以 **Root 手机分身（小米 8 Lite）** 作为物理级微信告警与控制兜底的**全自动、无人值守代理与号池自愈矩阵**。

### 2. 用户日常“唯一”需要做的操作（零心智负担）
1. 在 **CloakMulti** 中登录 Google 账号；
2. 在浏览器中保留 **蜂窝** 与 **星辰** 机场的登录态；
3. **其余所有环节（凭据流转、端口绑定、节点失效自愈、坏线去上游刷新、严重死锁隔离、微信推送）全部交给系统自动运转。只要微信没响警报，用户完全不用管。**

## 三、 深度病理剖析：为什么之前觉得“联动性差、太复杂”？

过去开发人员往往陷入“离线批处理”思维，导致系统之间存在**四大致命断裂**：

1. **凭据异构与 Chromium 文件独占锁冲突**：
   - CloakMulti 产物是磁盘 `user-data-dir`、SQLite Cookie；Flow-Tools 要的是 Labs Session Token；Antigravity 要的是 OAuth Refresh Token。
   - 过去依靠 `migrate_to_flowtools.py` 强杀浏览器、搞 NTFS 软链接、杀 Flow-Tools 进程重启，极易遭遇进程锁冲突、数据损坏。
2. **静态端口绑定与跨区漂移封号**：
   - Downstream（Flow-Tools / Antigravity）直接在配置文件中写死了端口号（如 21012）。
   - 过去节点一旦挂了，就要去改配置文件然后重启软件。由于缺乏同区约束，粗暴换节点导致账号从美国漂到香港，**直接触发 Google 异地安全拦截甚至废号**。
3. **上游节点更新断链（纯靠肉身运维）**：
   - 蜂窝和星辰的落地节点变动时，本地代理池失效。此前没有任何自动化抓手去上游刷新，全靠人工去客户端点“更新订阅”。
4. **异常静默与缺乏随身通知**：
   - 当遇到 Google 人机验证码、封号或机场欠费时，PC 端只会疯狂报错并重试（加速打死账号），在外的一帆根本收不到警报。

## 五、 现场真实资产对账：已实现 (70%) vs 待实装 (30%)

### 1. 已实现的核心资产（现成可用，绝不重复造轮子）
- **AgentProxyHub**:
  - 蜂窝（`21001-21080`）与星辰（`22001-22045`）共 125 个独立出口池就绪；
  - 生产副本位于 `D:\Program Files\AgentProxyHub`，内核 `mihomo.exe`，外部控制器 `21909`；
  - `mcp/server.py` 已提供 6 项工具，支持真实 TCP 探活与防送中国家识别。
- **Flow-Tools**:
  - 独立 Google Labs 媒体号池（ImageFX/VideoFX/Veo），Rust 8001 网关；
  - TLS Chrome 指纹模拟，batchexecute RPC 逆向视频通道，支持 JIT 换票；
  - 微信多模态调用及无限画布直连已实装。
- **Antigravity Tools**:
  - 8045 端口兼容 OpenAI `/v1` 反代网关；
  - Gemini 3.8 Flash、Claude 账号轮询与 7 核心账号粘性绑定。
- **Root 手机分身 (小米 8 Lite)**:
  - `adb reverse tcp:48921 tcp:48921` USB 硬件总线级穿透通道（延迟 < 5ms，免 WiFi）；
  - `SmsForwarder v3.5.0` 开源通知桥；
  - `AdbIME` 毫秒级文本广播注入；
  - 微信失焦 300ms 自动拉起与 Frida 16.7.19 微信内存直读通道。

### 2. 规划待实装的关键胶水逻辑（仅需补齐这 30%）
- [ ] **上游自动更新器 (`upstream_syncer.py`)**：当节点池可用率 < 30% 时，后台自动请求蜂窝/星辰订阅 URL，更新配置并重载内核；
- [ ] **虚拟端口策略组 (Virtual Port Routing)**：AgentProxyHub 的 `21012`、`21008` 等对外端口改为 Proxy Group，坏线时调 API 内部切换同区（US）新节点，Downstream 零感知；
- [ ] **CDP 内存凭据提炼**：CloakMulti 登录完成后直接从内存读取 Token，调用 Flow-Tools 的 `POST /api/manage/inject-account` 热装载，消灭杀进程与文件锁；
- [ ] **占位隔离池与告警 Webhook 钩子**：遇 Google 人机验证或账号封禁时，将该账号放入 Quarantine 池并向 `127.0.0.1:48921/alert` 发送告警 JSON。

## 六、 落地推进三部曲（清晰不乱）

### Phase 1: 虚端口热切与上游自动刷新（优先解决网络自愈）
1. 在 AgentProxyHub 模板中将关键端口转为策略组；
2. 编写 `upstream_syncer.py`，实现订阅失效时自动静默刷新；
3. **收益**：彻底告别人工到机场客户端点“更新订阅”，彻底告别修改 Downstream 配置文件和杀进程重启。

### Phase 2: CDP 内存提取与在线热装载（解决进号流转）
1. 在 CloakMulti 中加入一键导出/同步动作，经 CDP 抓取 Cookies；
2. 在 Flow-Tools 开放 HTTP 凭据注入端点；
3. **收益**：给一个新号，10 秒内双端自动点亮，不再撞文件锁。

### Phase 3: 占位隔离与微信直报打通（解决监控闭环）
1. 在 PC 端建立致命异常判定规则（连续 3 次同区无节点、命中二次验证）；
2. 命中后把账号挂起（Quarantine），并向手机端 `127.0.0.1:48921` 抛送告警；
3. 手机分身收到请求后调用极速输入，微信直接私聊一帆；
4. **收益**：平时完全撒手不管，遇到死锁看一眼微信通知即可。
