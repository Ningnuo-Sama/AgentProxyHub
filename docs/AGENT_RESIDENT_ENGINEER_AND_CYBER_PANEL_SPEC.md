## 一、 核心痛点与本次重构宗旨

1. **消灭形式主义运维大屏**：
   原有面板堆砌了启动、停止、测速、刷新、P1/SOCKS/HTTP 三格式导出等大量冷门低级按钮，信息密度冗余，未起到“一览”作用。
2. **掌握终极生死权**：
   虽然日常自愈由 Agent 托管，但面板**必须常驻醒目的「启动内核」与「停止内核」按钮**，确保人类用户拥有最后的物理拔电/点火权。
3. **雷达化与场景直达剥离**：
   人类不需要手动选场景复制。面板左侧仅保留两大核心皇冠业务的**精选高分出口雷达**：
   - **Google 专线群**（Gemini 3.8 Flash、Flow Labs，绑定 7 账号，严格同国防漂移锁）；
   - **Claude 专线群**（住宅高分原生出口，延迟与置信度动态监控）。
4. **引入零成本驻场工程师（GLM-4-Flash）**：
   在面板右侧内嵌对话控制台，接入智谱 **GLM-4-Flash**（零 API 成本、无每日 Token 上限、极速响应、原生支持 Function Calling）。赋予其网络调度、上游拉取、换绑自愈的大权限，有事直接打字使唤它。
5. **知识双向流通（OpenViking 闭环）**：
   - 工程师启动时注入核心网络铁律；排障遇到疑难杂症动态查阅 OpenViking；
   - 每次修网自愈成功后，**自动将标准经验 Markdown 沉淀回 OpenViking 知识库**，全系统所有 Agent 瞬间共享。
6. **桌面活体信使（鲸管家 Live2D 联动）**：
   告别冷冰冰的日志。网络自愈、订阅拉取或发生重大死锁时，工程师自动向桌面的**《鲸管家》**推送结构化通知，小虎鲸女仆在屏幕右下角顶出可爱情绪气泡与微动作。

### Task 1: 鲸管家极简本地通知接收器 (`jingguanjia-notify`)
* **目标文件**：`D:\GitHub\鲸管家\src\features\desktop-pet\main.ts`
* **改动要求**：
  在主进程中启动一个极其微型、纯原生的 `node:http` 服务（监听 `127.0.0.1:8766`），代码量控制在 25 行以内。
* **接口契约**：
  - **方法**：`POST /notify`
  - **入参 Payload**：
    ```json
    {
      "text": "主人！已帮 Claude 切换至日本原生高速出口 (45ms)～",
      "emote": "happy",     // 可选: happy | work | wronged | wave | sleepy | angry
      "motion": "wiggle"   // 可选: squash | wiggle | hop | random
    }
    ```
  - **行为**：
    收到后直接调用主进程已有函数：
    ```typescript
    announce(body.text, body.motion || 'wiggle');
    if (body.emote) showEmote(body.emote, 5000);
    ```
    返回 `HTTP 200 {"ok": true}`。
  - **进程纪律**：桌宠退出时（`app.quit()`）随之平滑关闭该 HTTP server，严禁遗留孤儿端口。

### Task 2: 驻场工程师桥接核心 (`core/resident_engineer.py`)
* **目标文件**：`D:\GitHub\AgentProxyHub\core\resident_engineer.py`
* **模型选型**：智谱 **GLM-4-Flash**（API 端点：`https://open.bigmodel.cn/api/paas/v4/chat/completions`，调用本地环境变量 `ZHIPU_API_KEY` 或配置文件中的 Key）。
* **内置 System Prompt（冷启动常识注入）**：
  ```text
  你是由智谱 GLM-4-Flash 驱动的 AgentProxyHub 专属驻场网络工程师。
  你的使命：以极高效率维护本地 125 个多出口专线，保障 Google 账号池与 Claude 出海环境绝对稳定。
  不可逾越的铁律：
  1. 绝对禁止跨国/跨大洲漂移换绑（如美区账号只能在 US 候选节点间切换，一旦跨区将导致账号彻底报废）；
  2. 蜂窝出口严格锁定端口段 21001-21080，星辰专线锁定 22001-22045；
  3. 排障遇到不确定的错误码，必须先调用 search_openviking 查阅历史经验，严禁盲目试错；
  4. 解决完网络故障后，必须调用 save_openviking 记录排障过程，并调用 notify_jingguanjia 给主人发桌面气泡战报。
  ```
* **挂载的 7 大 Function Calling 工具箱**：
  1. `get_network_status()`: 读取 `data/nodes.json` 与当前内核连接数，返回核心节点健康度。
  2. `pull_airport_subscription(provider)`: 请求蜂窝/星辰订阅链接，下载最新 YAML，触发 `core/gen-config.ps1` 并热重载内核。
  3. `test_port_target(port, target_url)`: 现场向端口发起真实 TCP/HTTP 测试，返回状态码与真实延迟。
  4. `rebind_account_proxy(email, new_port)`: 
     - **安全检查**：校验 `new_port` 对应国家是否与原端口国家严格一致；
     - 校验通过后原子写入 `data/bindings.json`，并触发 mihomo API 热重载。
  5. `search_openviking(query)`:
     - 请求 `http://127.0.0.1:1933/api/v1/search`，检索 `viking://user/windows/memories/experiences/`，返回历史踩坑总结。
  6. `save_openviking(title, content_md, tags)`:
     - 将排障经验以标准 Markdown 写入 `viking://user/windows/memories/experiences/network/<date>_<title>.md`。
  7. `notify_jingguanjia(text, emote, motion)`:
     - POST `http://127.0.0.1:8766/notify`，驱动桌面虎鲸女仆向主人展示气泡。
